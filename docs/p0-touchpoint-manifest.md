## C. 扩展目录裁定（P0 冻结）

- **自定义业务逻辑目录 = `src/extensions/`**（P1 先行选择，P0 正式沿用）。
- 迁移预演/检查工具属离线 tooling，不入 src/（src 必须保持 Workers 兼容：node:sqlite 只在
  Node 侧存在）：P7 工具在 `scripts/migration/` + `scripts/migration-rehearsal.ts`，
  测试夹具在 `tests/fixtures/`，均不是上游触点。
- 挂载规则：扩展模块放 `src/extensions/`，不散落进上游模块；上游文件只加最小调用接缝（A 表）；
  上游没有生态位的功能（如 baseline 三表）按现有惯例放 `src/db/v2/`、`src/memory/`、`src/gateway/` 的**新文件**（新增文件不算修改上游触点）。
- P2–P9 新增触点时必须同步登记本表 A/B 两节；新迁移一律 0018+ 编号。
- **P8 边界（2026-10-24）**：`migrations/` 只放全新部署可播放的迁移（tests readdirSync 全量播放）；
  "线上同库升级专用"迁移放 `migrations-p8/`（编号沿用 0021+ 语义），由 orchestrator / `wrangler d1
  execute` 按序播放，账本引导与 runbook 见 `scripts/migration/p8.ts` 头注释与 DEV.md。

## D. upstream 同步核对流程（P12 使用，平时小更新也可用）

1. `git fetch upstream` → 看 upstream/main 与本分支 diff 是否触及 A 表文件；
2. 触及的行逐条核对"插入目的"是否已有上游等价实现（上游做了 → 删本地接缝，登记"上游已替代"）；
3. 先跑 `tests/baseline.test.ts`、`tests/memory-weight.test.ts`（接缝测试），再跑全量 `npm run verify`；
4. 挂了先查本表"依赖的上游契约"列，不先怀疑扩展文件本身。
